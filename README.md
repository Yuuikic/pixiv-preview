# P²

<img src="assets/icon.png" width="128" alt="P² logo">

**P²: A browser extension for previewing Pixiv artworks, designed especially to work with Nazurin.**

[Privacy](PRIVACY.md) · [License](LICENSE)

一个轻量、免构建的 Chrome Manifest V3 插件。在 Pixiv 的作品网格中悬浮缩略图，即可在指针旁查看保持完整宽高比的高清图片。当前版本为 `0.11.0` 开发版。

## 功能

- 适用于关注动态、搜索、排行榜、收藏、用户主页等含作品卡片的 Pixiv 页面
- 默认只加载适合浮窗尺寸的 Pixiv 预览图，不请求原图
- 悬浮阈值到达后即以较大的方形浮窗显示模糊缩略图；取得元数据后再伸展为目标尺寸
- 浮窗跟随浏览器明暗主题；加载图片时使用模糊缩略图占位，完整图片就绪后平滑替换
- 取得作品宽高后，浮窗边框会从初始加载尺寸平滑伸展到目标尺寸
- 横图、纵图和长图均按比例完整显示，不进行方形裁切
- 默认浮窗不会跟随指针；离开缩略图后会短暂保留，便于跨过间隙进入浮窗
- 单页作品不显示冗余的 `1 / 1`；多页作品才显示页码和翻页按钮
- 浮窗出现时按 S、点击底栏“S 留驻”，或直接在浮窗内单击，可留驻；第一次直接拖动也会自动留驻并立即移动
- 留驻已有作品后仍可继续悬浮、留驻其他作品；同一作品在一个标签页内只保留一个浮窗
- 点击重叠浮窗会将它提到最上层；双击留驻窗或点击底栏 `×` 只关闭当前窗
- 第一次按 Esc 会隐藏当前标签页的全部浮窗；10 秒内未打开新预览时再次按 Esc，可将它们按原位置、尺寸和状态恢复
- 多页作品支持底栏按钮和键盘方向键翻页；留驻窗中的滚轮用于缩放
- 底栏工具区仅在留驻后启用，可代理点击 Pixiv 当前卡片的收藏按钮，并可在新标签页打开作品详情
- 兼容 Pixiv 的无限滚动和站内页面切换
- 当前标签页发生页面跳转、前进或后退时立即关闭预览并取消尚未完成的加载；按住 Cmd/Ctrl/Shift 在新标签页打开作品不会影响当前页浮窗
- 可在插件工具栏弹窗中调整悬浮触发延迟（100–3000ms，默认 500ms）和浮窗残留时间（0–1000ms，默认 500ms）
- “识别浮窗下方作品”默认开启：普通浮窗遮住其他缩略图时，仍可在达到触发延迟后切换；关闭后，指针进入浮窗即持续显示当前作品
- 可选择是否在预览图显示后继续加载原图（默认关闭）
- 作品元数据由插件后台按需读取，避免触发 Pixiv 页面自己的加载进度提示
- 可选连接自己的 Nazurin v2 服务，从预览窗口直接提交整个 Pixiv 作品
- 设置界面根据浏览器语言自动使用中文或英文；工具栏弹窗可打开独立设置标签页
- 留驻与 Nazurin 快捷键可配置，默认为 S 和 D
- 不进行 Pixiv 后台批量请求，不申请 Cookie、标签页或浏览器下载 API

## 安装

### GitHub Release

从项目的 Releases 页面下载 `P2-vX.Y.Z.zip` 并解压，然后按下面的步骤加载该文件夹。不要直接选择 ZIP 文件。

### 源码安装

1. 在 Chrome 地址栏打开 `chrome://extensions/`。
2. 打开右上角的“开发者模式”。
3. 点击“加载已解压的扩展程序”。
4. 选择本项目文件夹 `PixivPreview`。
5. 打开或刷新 Pixiv 页面。

更新代码后，请先在 `chrome://extensions/` 点击本插件的“重新加载”，然后刷新所有已打开的 Pixiv 标签页。Chrome 不会自动替换已经注入到旧页面中的内容脚本；工具栏设置页顶部会显示当前实际加载的插件版本，便于核对。

## 使用

将鼠标停在作品缩略图上至少 0.5 秒。短暂划过不会显示浮窗，也不会发起作品请求；达到阈值后会立即显示加载状态并读取元数据。取得作品宽高后，浮窗会保持可见并调整为正确比例，同时渐进加载 Pixiv 的 `regular` 预览资源。默认不会继续请求原图。

默认状态下，浮窗不会跟随指针移动。鼠标离开当前缩略图后，浮窗会按设置的“悬浮窗残留时间”短暂保留；在这段时间进入浮窗并单击即可留驻。如果指针指向另一张缩略图，包含被浮窗遮住的缩略图，旧浮窗会一直保留到新作品达到触发延迟并显示，然后才被替换。若更喜欢“进入浮窗后始终保持当前预览”，可关闭“识别浮窗下方作品”。

需要继续操作当前预览时，可以按 S、点击底栏“S 留驻”，或在浮窗内单击鼠标左键进入留驻状态。也可以直接按住图片区域或底栏空白处拖动，浮窗会在同一次手势中自动留驻并移动。留驻后可用滚轮或窗体边缘等比缩放；多页作品使用左右按钮或键盘方向键翻页。

存在普通悬浮预览时，S 会将当前预览加入留驻窗口；没有普通预览时，S 只取消最上层窗口的留驻，窗口会在当前位置按残留时间规则收起。点击某个窗口自己的“S 留驻”可切换该窗口的状态。第一次按 Esc 会暂时隐藏全部窗口；若 10 秒内没有打开新预览，再按一次 Esc 会原位恢复。新预览实际出现或 10 秒倒计时结束后，隐藏历史会被彻底清除。每个窗口底栏的 `×` 或在窗体内双击只关闭该窗口。

普通浮窗的收藏、打开作品和 Nazurin 工具会降低透明度并禁用；第一次点击该区域只会留驻浮窗，不会误触工具。留驻后，收藏工具会查找当前网页上该作品缩略图自己的收藏按钮并代理点击。如果无法可靠找到该按钮，收藏工具仍会保持禁用。图片形按钮会在新标签页打开作品详情。

点击 Chrome 工具栏中的 P² 图标，可以调整触发延迟、悬浮窗残留时间、遮挡时的作品识别方式、快捷键，也可以选择是否启用“加载原图”。弹窗右上角的图标会在标签页中打开完整设置页面。设置会自动保存，并立即应用到已经打开的 Pixiv 页面。

### Nazurin 快速收藏

Nazurin 配置默认折叠。在设置页填写 API Host 和 Telegram Bot Token，点击“保存”并批准该 API Origin 的可选访问权限，然后执行“测试连接”。测试会向真实 POST 路由发送缺少作品 URL 的空请求：Nazurin 在启动任务前以 400 拒绝它，因此不会创建下载任务，同时能避开部分反向代理拒绝 OPTIONS 导致的误报。Host 会自动补齐末尾 `/`；非本机 HTTP 地址会显示明文传输警告。配置只保存在 `chrome.storage.local`，不会进入 Chrome 同步。

只有配置已保存且连接测试成功时，浮窗中才会出现 Nazurin 按钮，Nazurin 快捷键才会生效。修改配置会立即撤销已验证状态，必须重新测试。

留驻窗口后，可点击 Nazurin 图标提交该作品。键盘操作无需先留驻：普通 D 提交当前最上层可见浮窗；Shift+D 截取触发时全部留驻窗口，按窗口层级从高到低加入队列。输入框、可编辑区域、按键自动重复以及 Cmd/Ctrl/Alt 组合键不会触发。多页作品也只发送一次作品详情 URL，由 Nazurin 收藏整部作品。

每个 Pixiv 标签页拥有独立队列，并发数为 1，前一个请求结束 1000ms 后才提交下一个。队列不自动重试；同一作品在排队或提交中时会跳过重复操作，完成后可手动再次提交。页面跳转会取消未提交项目并忽略迟到结果。

界面显示“已提交到 Nazurin”只代表 Nazurin API 已接受请求。实际下载与保存由 Nazurin 异步完成，最终结果请以 Telegram 消息为准。PixivPreview 不读取 Nazurin-extension 的配置、历史或状态，两者可独立同时安装。

## 权限与隐私

插件只在 `https://www.pixiv.net/*` 页面运行，不申请 `tabs`、`cookies`、`downloads`、`webRequest` 或通知权限。`storage.sync` 保存一般预览设置；Nazurin Host 与 Token 只保存在 `storage.local`。同一 Pixiv 主机的访问权限用于让插件后台按需读取作品元数据，从而不把该请求计入页面自身的加载状态。

配置 Nazurin 时，插件只请求用户填写的 API Origin 对应的可选 Host 权限。内容脚本只能向后台提交数字作品 ID；后台自行生成 `https://www.pixiv.net/artworks/{illustId}`，不会接受网页传入的任意 URL，也不会记录 Token、完整 API URL或服务器响应中的敏感内容。清除 Nazurin 配置时会同时移除对应可选权限。

## 已知限制

- Pixiv 动图首版只预览静态封面，不播放动画。
- 私密、已删除、受地区限制或当前账号无权查看的作品不会尝试绕过限制。
- Pixiv 的作品元数据接口不是公开 API。如果站点以后调整响应结构，需要更新 `src/content.js` 中的 `normalizeArtworkResponse()`。
- Nazurin 集成按 v2 的 `POST /{BOT_TOKEN}/api` 协议实现；连接测试依赖当前 v2 对缺少 `url` 的 POST 返回 400/422。

## 开发与发布

项目没有运行时依赖，也不需要构建。安装 Node.js 20 或更新版本后，可运行：

```sh
npm test
npm run check
npm run package
```

打包结果位于 `dist/P2-vX.Y.Z.zip`，只包含扩展运行所需文件、许可证、隐私说明和第三方声明，不包含测试与开发文件。

发布新版本时，使 `manifest.json`、`package.json` 与 README 中的版本号保持一致，提交代码后创建同版本 Git 标签：

```sh
git tag -a v0.11.0 -m "P² v0.11.0"
git push origin HEAD --follow-tags
```

推送 `vX.Y.Z` 标签后，GitHub Actions 会运行测试、校验标签版本、生成扩展 ZIP，并创建对应的 GitHub Release。
